## IV02: aggregate completion

Idle requires all known turns, submitted requests and executing callbacks to be
finished. Codex tracks pending turn IDs separately, so finishing B cannot retire
A. A callback remains active even if its native completion notification arrives
first. In-flight submission responses bind early completions to the returned
turn ID; unmatched or failed effects retain uncertainty. The callback lifetime
rule also applies to ACP and Grok paths. Unknown activity requires reconciliation
or a new connection; it does not become idle merely because a later turn ends.

The independent checker matches requested and completed callback identities and
arguments before accepting the latest aggregate idle. Applicable durable native
calls and operations in pending or unknown state veto completion. Unrelated work
does not. Fresh harness snapshots retain native calls alongside operations.

`test_aggregate_completion.py` exercises all six orders of three held callbacks
on each Codex, Claude and Grok adapter, early completion, duplicates, ambiguous
IDs and submission races. A deliberately false per-turn idle must fail both the
product activity oracle and the independent pending-callback check. Unrelated
exceptions do not earn detection credit. The original two-callback AB/BA witness
is retained unchanged in the published repair evidence.

## IV03: independent callback identity

A valid native observation cannot lend authority to a contradictory executed
callback. Both sides independently bind the native conversation, application
session, connection incarnation and call ID. Requested callbacks must support
completed callbacks. Normalization preserves each side's values, durable session
identity and actor provenance; it does not reconcile contradictions away.

Lifecycle retained-memory probes apply the same identity rule to their raw
observations. When an inner session or actor/source claim is explicitly present,
it must agree with the applicable binding. Historical compact fixtures without
those optional claims remain usable; explicit null or conflicting values fail.

`test_callback_identity.py` retains one-field contradictions, valid controls,
missing evidence and bypass calibrations for main callback and lifecycle joins.
The exact independent one-field witness and additional adversarial duplicate,
reassignment and actor cases are retained with raw reports.

## IV04: assertion attribution

Calibration credit requires the actual raising instruction in the selected test
frame to belong unambiguously to the intended AST assertion. The observer checks
instruction and assertion spans, including columns. An explicit unrelated raise
on the same line, an exception inside assertion evaluation, a different frame,
or unavailable positions cannot earn credit. Genuine failing assertions remain
detectable under both pytest rewriting and plain assertion modes.

`test_calibration_attribution.py` preserves the original calibrator controls and
adds same-line, multiline, inline, Unicode and ambiguous-position cases. The
twelve original source faults remain valid calibrations; this repair does not
dispute their earlier independent validation.
