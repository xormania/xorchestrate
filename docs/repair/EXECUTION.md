## Changed contracts and expectations

- Public delivery/native inspection projects each record under its actual access
  scope, including structured historical native results. Trusted internal receipt
  snapshots retain the full graph.
- Adapters optionally bind a replay-only application callback. It rechecks current
  authority/currentness from the durable ledger and never starts a missing effect.
  External bridge forwarding preserves this boundary. Custom callback caches keep
  their documented behavior when no application validator is bound.
- Assessments retain a material input binding. Default work projection excludes
  display/write bookkeeping; configured work_input_fields can explicitly consume
  those fields. Historical unbound assessments require reassessment.
- Claude completion is scoped to outstanding work; ambiguous observations retain
  uncertainty. Connection errors after issued effects retain recoverability.
- The checker retains independent native/application/effect observations and latest
  attempt order. Work replies must precede completion; held-tool replies may follow
  release. Calibration requires actual target assertion execution and exact marker,
  observed through a retained pytest observer; traceback source text cannot suffice.

These changes strengthen the existing H/B/A expectations. No owner requirement,
store, native protocol, provider selection, permission choice or concurrency path
has been removed. Installed-vendor native behavior is not inferred from peers.
