# F01: delivery inspection and historical native read results

The public delivery view now evaluates the configured inspection policy for
every returned record using that record's own work, message and session bindings.
Denied or review-required records are omitted. The selected message must remain
authorized. The internal receipt policy still receives the complete durable
snapshot, so scoped public access does not prevent trusted cross-work joins.

Native observation inspection applies the same rule to observations and durable
calls. A native source session can belong to a different work from the resource
selected by the executed arguments. Both bindings must authorize inspection.
This is read authority under the requested inspection action; a monitoring role
does not need authority to execute historical side effects. The original action
is exposed to policy in `inspection.action`, and `record` contains the retained
record being considered. Authorization contexts and observed records are
rechecked before returning the projection.

Historical native aggregate read results are projected recursively. A changed
public projection carries `inspection_redacted: true`; raw stored observations,
call results and receipt inputs remain unchanged. Actual target authorization
does not depend on a list of action names. Aggregate structure handling covers
the existing multi-resource work/session/message/delivery/native read results.

## Reproduced failure and controls

The original ZIP reproduction was run unchanged before repair against
`b0a00f1aed08d4ad8e066de8eb51f94e21da9f4a`, with fresh MemoryStore and SQLiteStore
instances. The public delivery response disclosed the private canary in both
`evidence` and `messages`. Direct private queries were denied and public
`get_work` omitted the canary. Its exit zero signifies successful defect
reproduction, not a product pass.

The same scenario after repair retains its controls and returns no leaked
sections. The original and repaired raw responses and scripts are retained
separately in the evidence package under `delivery_scope/original/` and
`delivery_scope/repaired/`.

The new product assertions were also run against the original candidate. Twelve
cases fail at `F01_NO_PRIVATE_RECORD_DISCLOSURE`; two unrelated-outage controls
pass. On the repaired working candidate, all eighteen cases in
`tests/hexagonal/test_delivery_scope.py` pass. The combined focused delivery and
adversarial suite passes 61 tests; Ruff passes. These are component measurements;
the final report identifies the subsequently committed integrated candidate and
its complete-suite measurement.

## Sustained calibration

`test_f01_sustained_global_snapshot_fault_is_detected` installs the original
unfiltered public snapshot behavior only on its isolated application instance.
It verifies activation, observes the real private canary, and requires the exact
`AssertionError` from `F01_NO_PRIVATE_RECORD_DISCLOSURE`. The same private-denial
and public-work controls remain valid while the faulty public read stays faulty.
Both stores run this fault in normal CI.

`test_f01_unrelated_inspection_error_receives_no_detection_credit` injects a
store-read TimeoutError. That error remains a TimeoutError and cannot satisfy
the disclosure assertion or receive target-detection credit. Fault planting
requires no brittle source replacement and does not edit the candidate or the
original review archive.

## Independent challenge and sibling paths

An in-session reviewer demonstrated an additional leak after the first
projection: a public session had historically called private `get_work`, and
its public-bound native envelope still disclosed the private result. The generic
executed-arguments binding now closes that path. Regressions cover both
`get_work` and `get_acceptance`, both stores, retained public history and direct
private denial. This challenge is separate from xor's later fresh-session review.

| Public read | Inspected scope and handling |
|---|---|
| `get_delivery` | Selected message plus separately authorized record projection; both stores exercised. |
| `native_observations` | Every call/observation's source and actual executed target; aggregate results recursively projected; both stores exercised. |
| `get_work` | Already filters assignments/evidence/sessions by selected work. Historical cross-work native read regression exercises target binding. |
| `get_acceptance` | Selected work basis; historical cross-work native read regression exercises target binding. |
| `get_operation` | Context derives the operation's actual work/session; generic historical-argument authorization uses that same resolution. Source inspected. |
| `inbox`, `list_work`, `list_sessions` | Explicit list scopes retain their existing policy; their nested native aggregates project each record. Source inspected. |
| `list_actors`, `capabilities`, `events` | Existing global catalog/journal permissions; no selected delivery message is used to authorize them. Source inspected, not redefined by F01. |
| `verify_exchange` | Full trusted snapshot retained. A receipt-policy control verifies private cross-work input remains available internally without appearing in the public delivery projection. |

The shared projection inspects related message attempts and session metadata,
including same-work messages explicitly denied by message ID. It does not infer
confidentiality labels from arbitrary caller/provider prose: configured policy
continues to govern the resource records that contain that data.

A bounded performance probe with five work items and 500 1-KiB native
observations returned exactly the authorized 100 observations in approximately
0.071 seconds for MemoryStore and 0.060 seconds for SQLiteStore on this Work
host. It is a diagnostic measurement, not a performance guarantee.

No native vendor credentials or Unix sockets are required for these cases.
These deterministic inspection results do not establish authenticated native
acceptance for the broader H1–H8 requirements. Relevant requirements are H5,
A2 and the B4/B5 calibration/evidence obligations.
